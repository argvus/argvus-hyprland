title: Hyprland 오버라이드
description: 패키지 파일을 편집하지 않고 ARGVUS Hyprland 구성을 사용자 지정하세요.
---
ARGVUS는 Hyprland를 커스터마이즈하는 두 가지 방법을 지원합니다. 두 가지를 혼동해서는 안 됩니다:

- `~/.config/hypr/hyprland.lua`는 전체 사용자 구성입니다. 이것이 유효하고 기본 Hyprland 템플릿이 아닌 경우, `argvus start`는 패키지된 구성 대신 이 파일로 Hyprland를 실행합니다.
- `~/.config/argvus/data/hypr/`는 점진적인 ARGVUS 오버라이드를 포함합니다. 패키지 구성은 기본으로 유지되며, 이 조각들을 마지막에 로드합니다.

대부분의 커스터마이즈에는 점진적 ARGVUS 오버라이드를 사용하세요. 이렇게 하면 ARGVUS 기본값, 생성된 상태, 세션 통합이 패키지 업데이트 동안에도 유지됩니다.

## 지원되는 오버라이드 파일

조각을 추가하기 전에 디렉토리를 생성하세요:

```sh
mkdir -p ~/.config/argvus/data/hypr
```
패키지된 구성은 이러한 파일이 존재할 때 다음 순서대로 로드합니다:

```text
~/.config/argvus/data/hypr/monitors.lua
~/.config/argvus/data/hypr/rules.lua
~/.config/argvus/data/hypr/bindings.lua
~/.config/argvus/data/hypr/user.lua
```
파일을 책임에 따라 사용하세요:

- `monitors.lua` — 추가 또는 교체 모니터 선언.
- `rules.lua` — 창 및 레이어 규칙.
- `bindings.lua` — 추가 키 바인딩 또는 사용자 정의 동작.
- `user.lua` — 이전 범주에 맞지 않는 환경 변수 및 기타 Lua 구성.

Lua 오류가 있는 조각(fragment)은 나머지 구성을 중단하지 않습니다. Hyprland는 해당 파일을 건너뛰고, 경로와 오류를 `ARGVUS: ignoring invalid user override`로 보고하며, 나머지 조각들은 여전히 로드합니다. 재로드하기 전에 `luac -p`가 있는 조각을 확인하세요.

`/usr/share/argvus/hyprland/config/hyprland.lua`는 편집하지 마세요. 이는 패키지 소유 파일로 업데이트에 의해 교체될 수 있습니다.

## 환경 덮어쓰기

세션 환경 값을 위해 `user.lua`를 사용하세요:

```lua
-- ~/.config/argvus/data/hypr/user.lua
hl.env("MY_VARIABLE", "1")
```
환경 변화는 세션에서 시작된 애플리케이션에 영향을 줍니다. 값이 전체 세션에 상속되어야 할 때는 로그아웃 후 다시 로그인해야 하며, 컴포지터를 다시 로드하는 것만으로는 이미 시작된 애플리케이션에는 충분하지 않습니다.

ARGVUS는 `XDG_CONFIG_DIRS`을 소유하며, 테마 전환으로 인한 리로드를 포함하여 매번 Hyprland 리로드 시 재구축합니다. 각 ARGVUS 구성 디렉토리는 한 번만 나타나며, 세션에서 상속된 항목은 그 이후에 반복 없이 유지되므로 값이 제한됩니다. 이전 버전에서 시작된 세션은 여전히 중복된 항목을 가질 수 있습니다; Kitty, `argvus terminal` 또는 `argvus --control-center`가 `Out of buffer space calling sprintf`와 함께 실패하면, 깨끗한 환경에서 시작하기 위해 로그아웃 후 다시 로그인하십시오.

## 키 바인딩 추가

ARGVUS 키 바인딩 매니페스트의 일부가 아닌 새 바인딩에는 `bindings.lua`를 사용하십시오:

```lua
-- ~/.config/argvus/data/hypr/bindings.lua
hl.bind("SUPER + SHIFT + T", hl.dsp.exec_cmd("kitty"))
```
컴포지터 작업을 위해 ARGVUS Lua 디스패처 도우미를 사용하세요:

```lua
-- Focus the next window with a custom shortcut.
hl.bind("SUPER + CTRL + Tab", hl.dsp.group.next())
```
바인딩은 패키지된 구성과 함께 평가됩니다. 조합을 선택하기 전에 기존 단축키와의 충돌을 확인하세요. 예를 들어 특별 바인딩을 정의할 때 적절한 옵션을 유지하세요:

```lua
hl.bind(
  "XF86AudioLowerVolume",
  hl.dsp.exec_cmd("wpctl set-volume @DEFAULT_AUDIO_SINK@ 5%-"),
  { locked = true, repeating = true }
)
```
컨트롤 센터는 기존 ARGVUS 바인딩을 변경하거나 비활성화하는 데 선호되는 방법입니다:

```sh
argvus control-center keybindings
```
이 변경 사항들은 `/keyboard_shortcuts` 아래에 정식으로 저장되며 `~/.config/argvus/data/generated/hypr/keybindings.lua`로 구체화됩니다. `bindings.lua`에 수동으로 생성된 바인딩은 제어 센터 매니페스트에 추가되지 않으며 복원 작업으로 관리되지 않습니다.

## 전체 네이티브 Hyprland 구성

`~/.config/hypr/hyprland.lua`는 오버레이 파일이 아닙니다. 이를 생성하면 `argvus start`가 이를 검증하고 전체 Hyprland 구성으로 사용합니다:

```sh
mkdir -p ~/.config/hypr
cp /usr/share/argvus/hyprland/config/hyprland.lua ~/.config/hypr/hyprland.lua
```
이 접근 방식은 완전한 제어를 제공하지만, 복사된 파일은 사용자의 책임이 됩니다. ARGVUS가 변경됨에 따라 파일이 오래될 수 있으며, ARGVUS 로더나 생성 상태 처리를 생략한 사용자 정의 파일은 ARGVUS 통합을 잃을 수 있습니다. 의도적으로 완전한 교체가 필요하지 않다면 위의 프래그먼트 파일을 선호하세요.

`AUTOGENERATED HYPRLAND CONFIG`를 포함한 기본 Hyprland 파일은 `argvus start`에 의해 무시되므로, 해당 파일이 있어도 ARGVUS 설정을 대체하지 않습니다. 사용자 정의 파일은 유효성 검사를 통과한 경우에만 선택됩니다. 유효성 검사가 실패하면 런처는 패키지된 파일로 되돌아갑니다.

## 적용 및 문제 해결

Lua 프래그먼트를 변경한 후에는 세션 구성을 다시 로드하세요:

```sh
argvus sessionctl reload
```
다시 로그인하기 전에 전체 Lua 파일을 검증하세요:

```sh
luac -p ~/.config/hypr/hyprland.lua
Hyprland --verify-config --config ~/.config/hypr/hyprland.lua
```
사용자 구성이 시작 시 거부되면 다음을 확인하세요:

```sh
grep -E "Hyprland Lua config|failed validation|using user Lua|fallback" \
  ~/.local/state/argvus/session.log
```
패키지된 소스와 헬퍼는 `/usr/share/argvus/hyprland/`에 있습니다. `~/.config/argvus/data/generated/` 아래의 생성된 파일은 파생 상태이므로, 생성된 출력을 직접 편집하지 말고 소유 설정이나 오버라이드 프래그먼트를 편집하세요.

Control Center 워크플로우에 대한 [키보드 단축키](/docs/argvus-hyprland/keyboard-shortcuts/)] 및 전체 구성 경로 참조에 대한 [파일 위치](/docs/reference/file-locations/)]를 참조하세요.

Shadow 렌더 파워는 Hyprland를 호출하기 전에 1–4(기본 4)로 제한됩니다. 여기에는 레거시 이펙트 프로젝션도 포함됩니다. 이는 이전 ARGVUS 릴리스에서 허용하는 값이 Hyprland 0.57에서 시작을 차단하는 것을 방지합니다.
