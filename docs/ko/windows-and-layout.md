title: 창과 레이아웃

---
ARGVUS는 타일 및 플로팅 창 배치를 위해 Hyprland를 사용합니다. 사용자용 레이아웃 제어는 세 개의 제어 센터 페이지에 있습니다: **제어 센터 → 외관 → 작업 표시줄** (위치, 공간 및 아이콘), **제어 센터 → 데스크톱 및 입력 → Hyprland → 창 → 공간**, 그리고 **제어 센터 → 데스크톱 및 입력 → Hyprland → 테두리**.

## 개념

```text
┌────────────────────────────────────┐
│          outer space / panel       │
│   ┌────────────┐  inner  ┌──────┐  │
│   │   window   │   gap    │window│  │
│   └────────────┘          └──────┘  │
│     border around each window       │
└────────────────────────────────────┘
```
- **창 간격(Window gaps)**은 타일형 창과 타일형 레이아웃의 외곽 사이의 공간을 의미합니다.
- **작업 표시줄(Taskbar) 또는 셸 간격(shell spacing)**은 작업 표시줄이나 패널 같은 데스크톱 표면 주변의 여백을 의미합니다. 이는 창 간격과 동일한 값이 아닙니다.
- **테두리(Borders)**는 창 주변에 그려진 보이는 가장자리를 말합니다. **가장자리 두께(Edge thickness)**는 표시 설정 페이지에서 노출되는 테두리 폭을 조절합니다.
- **둥글기(Rounding)**는 선택된 시각 모드의 일부입니다. 창을 이동시키는 대신 창 모서리 모양을 변경합니다.
- **패널 예약 및 보이는 여백(Panel reservation and visible margin)**은 별개의 문제입니다. 패널은 공간을 차지하거나 시각적으로 사용할 수 있지만, Hyprland는 여전히 활성화된 간격 상태에 따라 창을 배치합니다.

## 스티키(Sticky) 및 간격(Spaced) 모드

번들 테마 모드는 두 가지 시작 기하 구조를 제공합니다:

| 모드 | 창 동작 | 표면 처리 |
| --- | --- | --- |
| 스티키 | 기본적으로 내부 간격 `2`, 외부 간격 `0` | 네모난 모양, 컴팩트하고 화면 가장자리에 가까움 |
| 스페이스드 | 기본적으로 내부 간격 `10`, 외부 간격 `18` | 둥근 모양, 그림자 있고 여유 공간 많음; 작업 표시줄/셸 여백 기본값 `18` |

이 값들은 기본값일 뿐, 제한은 아님. 창 간격과 작업 표시줄 간격 페이지에서 창 간격과 작업 표시줄 여백을 독립적으로 저장할 수 있음. 테마나 모드를 변경하면 다른 효과적인 레이아웃 값이 반영될 수 있음.

## 레이아웃 컨트롤

각 컨트롤은 독립적이며 여기 나열된 페이지에 위치함:

- **작업 표시줄 → 위치** — 작업 표시줄 위치, 상단 또는 하단.
- **작업 표시줄 → 여백** — 작업 표시줄 상단, 왼쪽, 오른쪽, 하단 여백, 각각 `0`에서 `100`까지. Sticky는 기본적으로 하단 여백을 `2`로 설정; Spaced는 `18` 사용.
- **작업 표시줄 → 아이콘** — 작업 표시줄 유틸리티 그룹이 자동 또는 항상 확장 동작을 사용하는지 여부.
- **Hyprland → 창 → 여백** — 내부 간격 및 외부 상/좌/우/하 여백, 각각 `0`에서 `100`까지.
- **Hyprland → 테두리** — 일반 테두리: 둥근 모서리 활성화; 활성화 시 둥글기는 `2`에서 `10`까지 선택 가능. 테두리 두께도 여기에 설정, `0`에서 `10`까지.
- **Hyprland → 테두리 → 그림자** — 창 그림자, 기본값은 끔. 범위, 렌더링 강도, 날카로운 모서리, 오프셋 및 배율을 설정하며, 색상은 테마 강조색과 alpha `99`를 따르거나 색상 입력 시 설정 가능.

이 값들은 ARGVUS의 화면 상태에 기록되며, `argvus-config`는 이를 세션이 적용하는 생성된 Hyprland 파일에 투영합니다. 작업 표시줄 여백은 셸 표면의 위치를 변경합니다; 외부 창 간격은 타일링 된 창 영역을 변경합니다. 두 가지는 유사한 시각적 거리를 만들 수 있지만, 하나를 변경한다고 해서 다른 하나가 변경되지는 않습니다.

## 윈도우와 작업 공간

타일링된 창은 Hyprland가 활성 작업 공간에서 배열합니다. ARGVUS는 또한 플로팅 유틸리티 창을 지원합니다; `SUPER + SHIFT + Space`는 포커스 된 창을 타일링 레이아웃과 플로팅 레이아웃 간에 전환합니다. 작업 공간 이동과 창 포커스는 활성 키 바인딩 매니페스트에 의해 제어됩니다; [Keyboard shortcuts](/docs/argvus-hyprland/keyboard-shortcuts/)를 참조하세요.

패키지된 구성은 제어 센터, 스네이크 및 디스크 사용 분석기를 떠 있는 중앙 창으로 엽니다. 디스크 사용 분석기는 작업 표시줄 메모리 팝업과 동일한 초기 `1399 × 920` 지오메트리를 사용하며, 창이 열릴 때 창 클래스 규칙에 의해 적용됩니다. ARGVUS Focus와 ARGVUS Clock은 GTK 레이어 셸 팝업으로 작업 표시줄 옆에 고정되어 있으므로 타일링된 창이 아니며 Hyprland 창 규칙을 사용하지 않습니다. 시계 알람 카드(clock alarm card)는 별도의 레이어 표면(`argvus-clock-alarm`)입니다.

제어판은 모달이 열려 있는 동안 전체 모니터 레이어 표면을 사용합니다. 패키지된 규칙은 Polkit 에이전트, GTK 포털 및 KDialog 창을 떠 있게 하고 중앙에 배치하며 고정하도록 하여, 패널에서 실행되는 대화 상자가 모달 위에 유지되고 입력을 받을 수 있게 합니다.

`hyprpicker`은 `SUPER + P`와 함께 열렸을 때 Hyprland 애니메이션을 사용하지 않습니다. 이 예외는 색상 선택기에만 영향을 미치며, 다른 애니메이션은 계속 전역 설정을 따릅니다.

### 브라우저 및 IDE를 위한 작업 공간 배치

새 설치에서는 기본적으로 창 규칙이 정의되어 있지 않습니다. 예를 들어, argvus-config의 `hyprland.window_rules` 아래에서 애플리케이션별 작업 공간 배치 규칙을 추가할 수 있습니다:

```sh
argvus config get hyprland.window_rules
argvus config set hyprland.window_rules.browser.workspace 3
```
각 규칙에는 1부터 10까지의  `argvus-config` `workspace`와 `classes` 목록이 있습니다. `classes`의 항목들은 윈도우 클래스(대소문자 구분)에 대해 매칭되는 정규 표현식입니다, 예를 들어 `[Cc]ode.*` 또는 `jetbrains-.*`. 문자, 숫자 및 `._*+?-[]()|^$`만 허용됩니다. `argvus-config`는 규칙을 `generated/hypr/window-rules.lua`에 작성하며, Hyprland 구성에서 이를 로드합니다. 기본값을 변경하지 않고 규칙을 교체하려면, ARGVUS 데이터 디렉토리에 `hl.window_rule` 호출을 `rules.lua`에 추가하세요; 이들은 생성된 규칙 후에 로드됩니다.

## 먼저 변경할 사항

- 창이 답답하게 느껴진다면, 창 간격을 늘리거나 Spaced 모드를 사용하세요.
- 창이 화면 가장자리에서 너무 멀게 느껴진다면, 외부/작업 표시줄 간격을 줄이거나 Sticky 모드를 사용하세요.
- 작업 표시줄 위치를 변경한 후 작업 표시줄이 정렬되지 않은 것처럼 보인다면, 작업 표시줄 위치와 네 개의 작업 표시줄/셸 여백을 함께 확인하세요.
- 창이 시각 패널과 겹친다면, 창 간격을 변경하기 전에 패널과 작업 표시줄 레이아웃 설정을 확인하세요.

변경 사항은 ARGVUS 모양/세션 통합을 통해 적용됩니다. 가능한 경우 페이지의 재설정 기능을 사용하세요; 생성된 Hyprland 파일을 직접 편집하지 마세요.

## 창 흔들림

**Desktop & Input → Hyprland → Animations → Windows**를 열고
**Wobble** 컨트롤을 사용하세요. `wobble`를 검색하거나, 페이지를 직접 여세요:

```sh
argvus control-center hyprland animations windows
```
Wobble은 기본적으로 비활성화되어 있습니다. 그 ARGVUS 기본값은 강성 `100`, 감쇠 `10`, 질량 `1`, 강도 `1`, 그리고 메쉬 해상도 `8`입니다. 강성과 질량은 `0.0001–1000` 값을 허용하며, 감쇠 `0–1000`, 강도 `0–2`, 그리고 메쉬는 정수 `2–32`를 허용합니다. 메쉬 해상도를 높이면 렌더링 비용이 증가합니다. 화살표 키를 사용하여 값을 조정하거나 Enter를 눌러 직접 입력할 수 있습니다. **Wobble 기본값 복원**은 초안을 변경하며; **적용**은 모든 대기 중인 애니메이션 수정을 저장하고 세션을 재시작하지 않고 Hyprland를 한 번 다시 로드합니다. Animations 내에서 뒤로 이동하면 공유 초안이 유지됩니다.

글로벌 Animations 스위치는 Wobble을 억제하면서 개별 설정은 유지합니다. 표준 값은 ARGVUS 상태의 `effects.wobble_*`에 존재하며; `hypr/state.lua`는 생성되며 수동으로 편집해서는 안 됩니다.

이는 `argvus-hyprland`의 패키지 의존성에 의해 적용되며, **Hyprland 0.57.0 이상**이 필요합니다. 버전 0.56은 이 구성에서 지원되지 않습니다. 최대 강도는 [출시된 0.57.0 소스](https://github.com/hyprwm/Hyprland/blob/v0.57.0/src/config/values/ConfigValues.cpp)를 따르며, 이는 `2`로 제한하지만, 최신 문서에서는 `3`로 나와 있을 수 있습니다.

## 전역 창 모드

**Control Center → Desktop & Input → Hyprland → Windows → Mode**를 열고 **Tile Windows (기본값)** 또는 **Floating Windows**를 선택합니다. 동일한 선택기는 작업 표시줄 유틸리티 그룹의 창 모드 아이콘에서도 사용할 수 있습니다.

이 설정은 모든 모니터와 작업 공간에 적용되며 로그아웃 후에도 기억됩니다. 플로팅은 기존 애플리케이션 창과 새로 열린 창을 변환합니다. 타일은 이 정책에 의해 변환된 창만 복원하며, 이미 플로팅 상태인 대화 상자 및 다른 창은 계속 플로팅 상태로 유지됩니다. 플로팅 활성화 중에 명시적으로 고정된 창도 고정을 유지하기 위해 계속 플로팅 상태로 남습니다. 타일 레이아웃은 재계산되며, 이전의 정확한 분할 트리는 복원되지 않습니다.

`SUPER + SHIFT + Space`는 타일에서 정상적인 창별 동작을 유지합니다. 플로팅에서는 창을 다시 타일로 변경하지 않습니다. 패널, 작업 표시줄, 알림은 레이어 셸 표면이며 영향을 받지 않습니다. 전체 화면은 계속해서 Hyprland의 일반 동작을 사용하며, ARGVUS 최대화는 Spaced에서 여백을 유지합니다.

표준 환경 설정은 `/hyprland/window_mode`이며 `$XDG_CONFIG_HOME/argvus/config/hyprland.json`에 있습니다. 생성된 투영은 `data/generated/hypr/window-mode.lua`이며, 수정하지 마세요. 창별 복원 레지스트리는 `$XDG_RUNTIME_DIR/argvus` 아래에 위치하며, 합성기 인스턴스에 속하며 구성 재로드 시에도 유지됩니다. 새 세션에서는 재사용되지 않습니다.

애플리케이션이 대기 중이거나 실패한 경우, 인터페이스는 이를 저장된 환경 설정과 구별합니다. 다시 시도하려면 옵션을 다시 선택하세요. 합성기가 없는 경우, 환경 설정은 다음 로그인 시 저장됩니다.

## 창 버튼과 애플리케이션 바

플로팅 모드는 일반 애플리케이션 창에 **최소화(Minimize)**, **최대화 / 복원(Maximize / Restore)**, **닫기(Close)**가 포함된 ARGVUS 제목 표시줄을 추가합니다. 제목 표시줄을 더블 클릭하면 최대화가 전환됩니다. 추가 장식은 타일 모드와 전체 화면에서 숨겨집니다. 자체 컨트롤을 그리는 애플리케이션은 두 개의 바를 모두 표시할 수 있으며, 일관된 ARGVUS 컨트롤은 의도된 것입니다.

모든 모니터에서 두 번째 Waybar가 나타나며, 메인 작업 표시줄의 반대쪽 가장자리에 위치합니다. 이 바는 해당 모니터의 현재 작업 공간에 있는 창만 나열하며, 최소화된 창도 포함됩니다. 숨겨진 그룹 탭은 추가 항목을 생성하지 않습니다. 최소화된 항목은 원래 모니터/작업 공간 연관을 유지합니다. 비활성 창을 클릭하면 활성화되고, 활성 창을 클릭하면 최소화되며, 최소화된 창을 클릭하면 복원됩니다; 컨텍스트 메뉴에서는 복원, 최소화, 최대화/복원, 닫기가 제공됩니다. 알 수 없는 애플리케이션 아이콘은 창 기호로 대체됩니다. 항목을 활성화하거나 복원하면 포인터 위치가 유지됩니다. 보조 바는 효과적인 기본 CSS(색상, 글꼴, 테두리 및 둥글기)를 사용하며, 높이와 반대쪽 가장자의 반사된 여백을 가집니다.

`SUPER + Alt + Up`는 메인 바를 상단에, 윈도우 바를 하단에 배치합니다. `SUPER + Alt + Down`는 그 반대로 배치합니다. 방향을 반복하면 위치는 변경되지 않습니다. 타일에는 메인 바만 있습니다. 타일로 돌아가면 윈도우 바를 제거하기 전에 최소화된 모든 창을 복원하고, 그 후 원래의 타일/플로팅 정책을 유지합니다.

최소화는 예약된 `special:argvus-minimized` 작업 공간을 사용합니다. 해당 작업 공간을 수동으로 사용하지 마십시오. `argvus windows service` 프로세스는 컴포지터 인스턴스별 런타임 레지스트리에 `$XDG_RUNTIME_DIR/argvus` 아래에서 정체, 원래 작업 공간/모니터, 지오메트리, 전체 화면/최대화 및 고정 상태를 기록합니다. 기록은 서비스 재시작이나 설정 다시 불러오기 후에도 남아 있지만, 컴포지터 세션 간에는 공유되지 않습니다. 창을 닫으면 해당 기록이 삭제됩니다. 모니터가 사라지면 복원은 사용 가능한 출력으로 수행됩니다. 누락되었거나 복구 바가 실패하면 새로운 최소화가 불가능하며, 복구 실패 시 기록과 복구 바는 유지됩니다.

세션은 `argvus-windows.service` 및 `argvus-window-bar.service`을 소유합니다. 후자는 Tile에서 Waybar 하위 요소를 대기 상태로 유지합니다. hyprbars 플러그인은 `argvus-hyprland`에서 번들로 제공되며, x86_64에서 Hyprland 0.57.0 ABI용으로 빌드되었습니다; 사용자의 홈 디렉토리에서 컴파일되지 않았습니다. 컴포지터 ABI 업데이트 시 플러그인을 다시 빌드하십시오.
명령어: `argvus windows list --json`, `watch --json`, `position top|bottom`, `restore-all`, `minimize|restore|activate|maximize|close ADDRESS`. 윈도우 주소는 목록에서 가져옵니다. `position top --persist`는 메인 바를 재시작하지 않고도 설정을 저장/프로젝트합니다. 구성 및 런타임 오류 세부 정보는 저널에 기록되며, 눈에 보이는 작업 실패는 번역된 알림으로 표시됩니다.

**Spaced + Floating** 모드에서는 윈도우가 외부 간격과 두 바에서 예약된 영역을 존중합니다. 경계는 테두리와 제목을 포함하며, 제목은 같은 윈도우 테두리 안에 위치합니다. ARGVUS 컨트롤을 통해 최대화하면 이 영역이 여백과 함께 채워지고, 복원하면 서비스 재시작 후에도 이전 기하 구조를 복원합니다. 전체 화면 모드는 여전히 전체 출력 영역을 사용합니다. 플로팅 윈도우는 겹칠 수 있으며, 타일링 내부 간격은 윈도우를 분리하지 않습니다.

`SUPER + Alt + Space`는 전역 타일/플로팅 모드를 전환하며, 작업 표시줄 및 제어 센터와 동일한 환경 설정을 사용합니다. 동등한 명령은 `argvus config window-mode toggle`입니다. 동시에 호출되는 경우 직렬 처리되며, 애플리케이션이 대기 중일 때도 저장된 환경 설정을 사용하여 전환합니다. 바로 가기는 키보드 단축키에서 변경하거나 비활성화할 수 있으며, `SUPER + Shift + Space`는 개별 창 동작을 유지합니다.
