ARGVUS は、タイル型およびフローティング型のウィンドウ配置に Hyprland を使用します。ユーザー向けのレイアウトコントロールは、3 つのコントロールセンターページにあります: **コントロールセンター → 外観 → タスクバー**（位置、スペース、アイコン）、**コントロールセンター → デスクトップ＆入力 → Hyprland → ウィンドウ → スペース**、および **コントロールセンター → デスクトップ＆入力 → Hyprland → 境界線**。

## 概念

```text
┌────────────────────────────────────┐
│          outer space / panel       │
│   ┌────────────┐  inner  ┌──────┐  │
│   │   window   │   gap    │window│  │
│   └────────────┘          └──────┘  │
│     border around each window       │
└────────────────────────────────────┘
```
- **ウィンドウギャップ** は、タイル状に並べられたウィンドウとタイルレイアウトの外端との間のスペースです。
- **タスクバーやシェルの間隔** は、タスクバーやパネルなどのデスクトップ表面の周囲の余白です。ウィンドウギャップとは異なる値です。
- **境界線** は、ウィンドウの周囲に描かれる視覚的な端のことです。**エッジの太さ** は、外観ページで表示される境界線の幅を制御します。
- **角の丸み** は、選択したビジュアルモードの一部です。これはウィンドウを移動させるのではなく、ウィンドウの角の形状を変更します。
- **パネルの予約と表示マージン** は別の問題です：パネルはスペースを占有するか、視覚的に使用することができますが、Hyprlandは依然としてアクティブな間隔状態に従ってウィンドウを配置します。

## スティッキーおよびスペースモード

バンドルされたテーマモードは、2つの初期ジオメトリを提供します:

| モード | ウィンドウの挙動 | サーフェスの処理 |
| --- | --- | --- |
| スティッキー | 内部ギャップ `2`、外部ギャップ `0` がデフォルト | 角ばっており、コンパクトで画面端に近い |
| スペースド | 内部ギャップ `10`、外部ギャップ `18` がデフォルト | 角が丸く、影付きでよりゆったりしている；タスクバー / シェルのマージンはデフォルトで `18` |

これらはデフォルトであり、制限ではありません。ウィンドウスペースおよびタスクバースペースのページでは、ウィンドウギャップおよびタスクバーマージンを独立して保存できます。テーマやモードを変更すると、異なる効果的なレイアウト値が反映されることがあります。

## レイアウトコントロール

各コントロールは独立しており、ここに記載されているページに存在します:

- **タスクバー → 位置** — タスクバーの位置、上端または下端。
- **タスクバー → マージン** — タスクバーの上・左・右・下のマージン、それぞれ`0`から`100`まで。Stickyは下のマージンを`2`にデフォルト設定；Spacedは`18`を使用。
- **タスクバー → アイコン** — タスクバーのユーティリティグループが自動展開か、常に展開かを使用するか。
- **Hyprland → ウィンドウ → マージン** — 内側の隙間と上・左・右・下の外側の隙間、それぞれ`0`から`100`まで。
- **Hyprland → ボーダー** — 一般的なボーダー: 角を丸くするを有効化；有効な場合、丸めは`2`から`10`まで選択可能。エッジの厚さもここで設定、`0`から`10`まで。
- **Hyprland → ボーダー → シャドウ** — ウィンドウの影、デフォルトでオフ。範囲、描画パワー、シャープコーナー、オフセットとスケールを設定し、その色はテーマのアクセントに従いアルファ`99`を使用、色を入力しない限り。

これらの値はARGVUSの外観状態に書き込まれ、`argvus-config`が生成されたHyprlandファイルに投影し、そのセッションが適用します。タスクバーのマージンはシェルの表面の位置を変更し、外側のウィンドウギャップはタイル状のウィンドウ領域を変更します。これらは類似の視覚的距離を生むことがありますが、一方を変更しても他方は変更されません。

## ウィンドウとワークスペース

タイル状のウィンドウはアクティブなワークスペース上でHyprlandによって配置されます。ARGVUSは浮動ユーティリティウィンドウもサポートしています; `SUPER + SHIFT + Space`はフォーカスされたウィンドウをタイル状と浮動レイアウトの間で切り替えます。ワークスペースの移動とウィンドウのフォーカスは、アクティブなキー割り当てマニフェストによって制御されます。[キーボードショートカット](/docs/argvus-hyprland/keyboard-shortcuts/)を参照してください。

パッケージ化された設定では、コントロールセンター、スネーク、およびディスク使用量アナライザーをフローティングで中央に配置されたウィンドウとして開きます。ディスク使用量アナライザーは、タスクバーのメモリポップアップと同じ初期 `1399 × 920` ジオメトリを使用しており、ウィンドウが開かれたときにそのウィンドウクラスルールによって適用されます。ARGVUS フォーカスと ARGVUS クロックは、タスクバーの横に固定された GTK レイヤーシェルのポップアップであるため、タイルウィンドウではなく、Hyprland のウィンドウルールを使用しません。クロックのアラームカードは別のレイヤーサーフェス（`argvus-clock-alarm`）です。

コントロールパネルは、そのモーダルが開かれている間、フルモニターレイヤーサーフェスを使用します。パッケージ化されたルールは Polkit エージェント、GTK ポータル、および KDialog ウィンドウをフロート、中央配置、ピン固定することで、パネルから起動されたダイアログがモーダルの上に表示され、入力を受け取れるようにしています。

`hyprpicker` は `SUPER + P` と共に開かれた場合、Hyprland のアニメーションを使用しません。この例外はカラーピッカーにのみ影響し、他のアニメーションは引き続きグローバル設定に従います。

### ブラウザとIDEのワークスペース配置

新規インストールでは、デフォルトでウィンドウルールは定義されていません。argvus-configの`hyprland.window_rules`下に、アプリケーションごとのワークスペース配置ルールを追加することができます。例えば:

```sh
argvus config get hyprland.window_rules
argvus config set hyprland.window_rules.browser.workspace 3
```
各ルールには1から10までの `argvus-config` `workspace`と`classes`リストがあります。`classes`のエントリはウィンドウクラスに対して正規表現でマッチします（大文字と小文字を区別）、例として`[Cc]ode.*`や`jetbrains-.*`があります。文字、数字、および`._*+?-[]()|^$`のみが許可されます。`argvus-config`はルールを`generated/hypr/window-rules.lua`に書き込み、Hyprlandの設定がそれを読み込みます。既定値を変更せずにルールを置き換えるには、ARGVUSデータディレクトリに`hl.window_rule`の呼び出しを`rules.lua`に追加してください。これらは生成されたルールの後に読み込まれます。

## 最初に変更するもの

- ウィンドウが窮屈に感じる場合は、ウィンドウ間隔を広げるか、スペースモードを使用してください。
- ウィンドウが画面端から遠すぎる場合は、外側/タスクバーの間隔を減らすか、スティッキーモードを使用してください。
- タスクバーの位置を変更した後にタスクバーがずれて表示される場合は、タスクバーの位置と4つのタスクバー/シェルの余白すべてを確認してください。
- ウィンドウがビジュアルパネルと重なる場合は、ウィンドウ間隔を変更する前にパネルとタスクバーのレイアウト設定を確認してください。

変更はARGVUSの外観/セッション統合を通じて適用されます。可能な場合はページのリセット機能を使用してください。生成されたHyprlandファイルを直接編集しないでください。

## ウィンドウの揺れ

**デスクトップ & 入力 → Hyprland → アニメーション → ウィンドウ** を開き、
**Wobble** コントロールを使用してください。`wobble`を検索するか、ページを直接開いてください:

```sh
argvus control-center hyprland animations windows
```
Wobbleはデフォルトで無効になっています。ARGVUSのデフォルトは、剛性`100`、減衰`10`、質量`1`、強度`1`、およびメッシュ解像度`8`です。剛性と質量は`0.0001–1000`、減衰`0–1000`、強度`0–2`、およびメッシュは整数`2–32`を受け入れます。メッシュ解像度が高いほどレンダリングコストが上がります。値を調整するには矢印キーを使用するか、直接入力するにはEnterを押してください。**Wobbleのデフォルトを復元**はドラフトを変更し、**適用**は保留中のすべてのアニメーション編集を保存し、セッションを再起動せずにHyprlandを一度リロードします。Animations内で戻ると共有ドラフトが保持されます。

グローバルなAnimationsスイッチは、個別の設定を保持しながらWobbleを抑制します。正式な値はARGVUS状態の`effects.wobble_*`に存在し、`hypr/state.lua`は生成され、手動で編集してはいけません。

これはHyprland **0.57.0以降** を必要とし、`argvus-hyprland`のパッケージ依存関係によって強制されます。バージョン0.56はこの構成ではサポートされていません。強度の最大値は[リリースされた0.57.0ソース](https://github.com/hyprwm/Hyprland/blob/v0.57.0/src/config/values/ConfigValues.cpp)に従っており、`2`までに制限されています。新しいドキュメントでは`3`が記載されている場合があります。

## グローバルウィンドウモード

**コントロールセンター → デスクトップ & 入力 → Hyprland → ウィンドウ → モード** を開き、**ウィンドウをタイル表示 (デフォルト)** または **ウィンドウを浮動表示** を選択します。同じセレクターはタスクバーのユーティリティグループのウィンドウモードアイコンからも利用できます。

この設定はすべてのモニターとワークスペースに適用され、ログアウト後も記憶されます。フローティングは既存のアプリケーションウィンドウと新規に開かれるウィンドウを変換します。タイルはこのポリシーで変換されたウィンドウのみを復元し、すでにフローティングになっていたダイアログやその他のウィンドウはフローティングのままです。フローティングが有効なときに明示的にピン留めされたウィンドウも、そのピンを保持するためにフローティングのままです。タイルレイアウトは再計算されますが、正確な以前の分割ツリーは復元されません。

`SUPER + SHIFT + Space`はタイル時に通常のウィンドウごとの動作を維持します。フローティングではウィンドウをタイルに戻すことはありません。パネル、タスクバー、通知はレイヤーシェルのサーフェスであり、影響を受けません。全画面表示は引き続きHyprlandの通常の動作を使用し、ARGVUSの最大化はSpacedにおいてマージンを保持します。

標準の優先設定は`/hyprland/window_mode`で、`$XDG_CONFIG_HOME/argvus/config/hyprland.json`にあります。生成された投影は`data/generated/hypr/window-mode.lua`であり、編集しないでください。ウィンドウごとの復元レジストリは`$XDG_RUNTIME_DIR/argvus`の下にあり、コンポジターインスタンスにスコープされ、設定の再読み込み後も維持されます。新しいセッションでは再利用されません。

アプリケーションが保留中または失敗した場合、インターフェースは保存された優先設定と区別します。オプションを再度選択して再試行してください。コンポジターがない場合、優先設定は次回のログイン時に保存されます。

## ウィンドウボタンとアプリケーションバー

フローティングモードでは、通常のアプリケーションウィンドウに**最小化**、**最大化 / 復元**、**閉じる**のあるARGVUSタイトルバーが追加されます。タイトルバーをダブルクリックすると最大化が切り替わります。追加の装飾はタイルモードおよびフルスクリーンでは非表示になります。独自のコントロールを描画するアプリケーションでは、両方のバーが表示される場合があります。統一されたARGVUSコントロールは意図的です。

セカンドWaybarは、すべてのモニターに表示され、メインタスクバーとは反対の端に配置されます。そのモニターの現在のワークスペースのウィンドウのみを一覧表示し、最小化されたウィンドウも含まれます。非表示のグループタブは追加のエントリを作成しません。最小化されたエントリは元のモニター／ワークスペースの関連付けを保持します。非アクティブウィンドウをクリックするとアクティブ化され、アクティブウィンドウをクリックすると最小化され、最小化されたウィンドウをクリックすると復元されます。そのコンテキストメニューには、復元、最小化、最大化／復元、閉じるが用意されています。未確認のアプリケーションアイコンはウィンドウのシンボルが代わりに表示されます。エントリをアクティブ化または復元してもポインタの位置は保持されます。セカンダリバーは、実際のプライマリCSS（色、フォント、ボーダー、角の丸み）を使用し、高さと反対側の端のミラーされたマージンを持ちます。

`SUPER + Alt + Up`はメインバーを上に、ウィンドウバーを下に配置します。`SUPER + Alt + Down`はその逆を行います。同じ方向を繰り返すと、位置は変更されません。タイルにはメインバーのみがあります。タイルに戻ると、ウィンドウバーを削除する前にすべての最小化されたウィンドウを復元し、その後、元のタイル/フローティングのポリシーを保持します。

最小化は予約済みの`special:argvus-minimized`ワークスペースを使用します。そのワークスペースを手動で使用しないでください。`argvus windows service`プロセスは、識別情報、元のワークスペース/モニター、ジオメトリ、フルスクリーン/最大化およびピン状態を、`$XDG_RUNTIME_DIR/argvus`の下にあるコンポジターインスタンス固有の実行時レジストリに記録します。記録はサービスの再起動や設定の再読み込みによっても保持されますが、コンポジターセッションを超えることはありません。ウィンドウを閉じると、その記録は削除されます。モニターが消えた場合、復元には利用可能な出力が使用されます。バーが存在しないか復元に失敗した場合、新しい最小化はできません。復元に失敗した場合、記録と復元バーは保持されます。

セッションは`argvus-windows.service`および`argvus-window-bar.service`を所有します。後者はWaybarの子プロセスをTileで休止状態に保ちます。hyprbarsプラグインは`argvus-hyprland`で同梱されており、x86_64上のHyprland 0.57.0 ABI向けにビルドされています。ユーザーのホームディレクトリではコンパイルされていません。コンポジターのABIが更新された場合、プラグインを再ビルドしてください。コマンド: `argvus windows list --json`、`watch --json`、`position top|bottom`、`restore-all`、および `minimize|restore|activate|maximize|close ADDRESS`。ウィンドウアドレスはリストから取得されます。`position top --persist` はメインバーを再起動せずに設定を保存/適用します。構成および実行時のエラーの詳細はジャーナルに書き込まれます。表示されるアクションの失敗も翻訳された通知として表示されます。

**Spaced + Floating** では、ウィンドウは外側のギャップと両方のバーによって確保された領域を尊重します。ボーダーとタイトルを含む境界は、同じウィンドウボーダー内にタイトルが配置されます。ARGVUS コントロールを使った最大化は、この領域をマージン付きで埋めます。復元するとサービス再起動後も以前のジオメトリを回復します。フルスクリーンは依然として出力全体を使用します。フローティングウィンドウは重なり合う可能性があります。タイル内の内部ギャップはそれらを分離しません。

`SUPER + Alt + Space` は、タスクバーやコントロールセンターと同じ設定を使用して、グローバルなタイル/フローティングモードを切り替えます。同等のコマンドは `argvus config window-mode toggle` です。同時呼び出しは直列化されます。切り替えは、アプリケーションが保留中の場合でも保存された設定を使用します。ショートカットはキーボードショートカットで変更または無効にできます；`SUPER + Shift + Space` は個別ウィンドウの動作を維持します。
