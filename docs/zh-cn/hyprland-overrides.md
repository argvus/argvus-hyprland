---
title: Hyprland 覆盖
description: 在不编辑封装文件的情况下自定义 ARGVUS Hyprland 配置。
---
ARGVUS 支持两种不同的方式来定制 Hyprland。它们不能混淆：

- `~/.config/hypr/hyprland.lua` 是一个完整的用户配置。当它有效且不是 Hyprland 的默认模板时，`argvus start` 会使用该文件启动 Hyprland，而不是使用打包的配置。
- `~/.config/argvus/data/hypr/` 包含增量的 ARGVUS 覆盖。打包的配置仍然作为基础，并在最后加载这些片段。

对于大多数自定义操作，请使用增量的 ARGVUS 覆盖。它们可以在软件包更新时保持 ARGVUS 默认设置、生成状态和会话集成可用。

## 支持的覆盖文件

在添加片段之前，请先创建目录：

```sh
mkdir -p ~/.config/argvus/data/hypr
```
当存在时，打包的配置按以下顺序加载这些文件：

```text
~/.config/argvus/data/hypr/monitors.lua
~/.config/argvus/data/hypr/rules.lua
~/.config/argvus/data/hypr/bindings.lua
~/.config/argvus/data/hypr/user.lua
```
按责任使用文件：

- `monitors.lua` — 额外或替换的显示器声明。
- `rules.lua` — 窗口和图层规则。
- `bindings.lua` — 额外的键绑定或自定义操作。
- `user.lua` — 环境变量和其他不符合前述类别的 Lua 配置。

带有 Lua 错误的片段不会停止其余配置。Hyprland 会跳过该文件，报告 `ARGVUS: ignoring invalid user override` 及其路径和错误，并仍然加载剩余的片段。重新加载前，请检查带有 `luac -p` 的片段。

不要编辑 `/usr/share/argvus/hyprland/config/hyprland.lua`。它是软件包拥有的，可以通过更新被替换。

## 环境覆盖

使用 `user.lua` 设置会话环境值：

```lua
-- ~/.config/argvus/data/hypr/user.lua
hl.env("MY_VARIABLE", "1")
```

环境变化会影响会话启动的应用程序。当需要整个会话继承该值时，请注销并重新登录；仅重新加载合成器对于已经启动的应用程序是不够的。

ARGVUS 拥有 `XDG_CONFIG_DIRS`，并在每次 Hyprland 重新加载时重建它，包括由主题切换触发的重新加载。每个 ARGVUS 配置目录只出现一次，从会话继承的条目会在其后保留而不会重复，因此值保持有限。由早期版本启动的会话仍可能携带重复条目；如果 Kitty、`argvus terminal` 或 `argvus --control-center` 与 `Out of buffer space calling sprintf` 发生冲突，请注销并重新登录以在干净的环境中启动。

## 添加键绑定

对于不属于 ARGVUS 键绑定清单的新绑定，请使用 `bindings.lua`：

```lua
-- ~/.config/argvus/data/hypr/bindings.lua
hl.bind("SUPER + SHIFT + T", hl.dsp.exec_cmd("kitty"))
```
使用 ARGVUS Lua 分发器助手进行合成器操作：

```lua
-- Focus the next window with a custom shortcut.
hl.bind("SUPER + CTRL + Tab", hl.dsp.group.next())
```
绑定会与打包的配置一起评估。在选择组合之前，请检查与现有快捷键的冲突。在定义特殊绑定时保留适当的选项，例如：

```lua
hl.bind(
  "XF86AudioLowerVolume",
  hl.dsp.exec_cmd("wpctl set-volume @DEFAULT_AUDIO_SINK@ 5%-"),
  { locked = true, repeating = true }
)
```
控制中心是更改或禁用现有 ARGVUS 绑定的首选方式：

```sh
argvus control-center keybindings
```
这些更改以规范形式存储在 `/keyboard_shortcuts` 下，并具体化为 `~/.config/argvus/data/generated/hypr/keybindings.lua`。手动创建的 `bindings.lua` 绑定不会被添加到控制中心清单中，也不会被其恢复操作管理。

## 完整的原生 Hyprland 配置

`~/.config/hypr/hyprland.lua` 不是覆盖文件。如果你创建它，`argvus start` 会验证它并将其作为完整的 Hyprland 配置使用：

```sh
mkdir -p ~/.config/hypr
cp /usr/share/argvus/hyprland/config/hyprland.lua ~/.config/hypr/hyprland.lua
```
这种方法提供了完全的控制，但复制的文件将由你自己负责。随着 ARGVUS 的变化，它可能会变得过时，而省略 ARGVUS 加载器或生成状态处理的自定义文件可能会失去 ARGVUS 集成。除非你有意需要一个完整的替代文件，否则建议使用上述片段文件。

包含 `AUTOGENERATED HYPRLAND CONFIG` 的默认 Hyprland 文件会被 `argvus start` 忽略，因此它的存在不会替换 ARGVUS 配置。只有在验证通过后，自定义用户文件才会被选用；如果验证失败，启动器将回退到打包文件。

## 应用与故障排除

更改 Lua 片段后，重新加载会话配置：

```sh
argvus sessionctl reload
```
在再次登录之前验证完整的 Lua 文件：

```sh
luac -p ~/.config/hypr/hyprland.lua
Hyprland --verify-config --config ~/.config/hypr/hyprland.lua
```
如果用户配置在启动期间被拒绝，请检查：

```sh
grep -E "Hyprland Lua config|failed validation|using user Lua|fallback" \
  ~/.local/state/argvus/session.log
```
打包的源文件和辅助文件位于 `/usr/share/argvus/hyprland/`。位于 `~/.config/argvus/data/generated/` 的生成文件是派生状态；请编辑所属设置或覆盖片段，而不是直接编辑生成的输出。

请参阅 [Control Center 工作流程的键盘快捷键](/docs/argvus-hyprland/keyboard-shortcuts/) 和 [完整配置路径参考的文件位置](/docs/reference/file-locations/)。

在调用 Hyprland 之前，影子渲染功率被限制在 1–4（默认 4），包括传统效果投影。这可以防止旧版本 ARGVUS 接受的值阻止在 Hyprland 0.57 上启动。
